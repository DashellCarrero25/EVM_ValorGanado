## Why

Antes de iniciar el desarrollo, es fundamental asegurar que todos los casos borde, validaciones, flujos de usuario, modelo de datos y dependencias técnicas estén claros y alineados. Esto previene retrabajo, errores y facilita la colaboración efectiva del equipo.

## What Changes

- Creación de un checklist previo a codificación para revisar specs, validaciones y flujos.
- Definición de criterios de aceptación para casos borde y validaciones clave.
- Revisión y documentación de flujos de usuario críticos (login, recuperación de contraseña, errores comunes).
- Validación del modelo de datos frente a escenarios previstos y relaciones entre entidades.
- Alineación del equipo en dependencias técnicas, convenciones de ramas, commits y PRs.

## Capabilities

### New Capabilities
- `pre-coding-checklist`: Checklist y criterios de revisión previos a desarrollo.
- `user-flows-review`: Documentación y validación de flujos de usuario críticos.
- `data-model-review`: Validación y ajuste del modelo de datos relacional.
- `team-alignment`: Alineación en dependencias técnicas y convenciones de trabajo.

- (Ninguna por ahora)

## Impact

- Specs y documentación de requisitos.
- Modelo de datos y relaciones.

- Herramientas, librerías y procesos de trabajo del equipo.
